# Hyperledger Caliper Implementation Plan

This document outlines the end-to-end plan for stress testing and performance testing both the **Single-Channel** and **Multi-Channel** crowdfunding architectures using **Hyperledger Caliper**.

## What is Hyperledger Caliper?
Hyperledger Caliper is a blockchain benchmark tool. It allows us to measure the performance of a specific blockchain implementation with a set of predefined use cases. It will produce an HTML report detailing:
- **Throughput (TPS)**: Transactions per second.
- **Latency**: Min, Max, Average response times.
- **Success/Fail Rate**: Ensure no transactions are lost under high load.

## Phase 1: Caliper Workspace Setup

We will initialize a new npm workspace dedicated to Caliper:

```bash
mkdir -p /root/crowdfunding/caliper-workspace
cd /root/crowdfunding/caliper-workspace
npm init -y
npm install --only=prod @hyperledger/caliper-cli@0.5.0
npm install --only=prod @hyperledger/fabric-gateway
npx caliper bind --caliper-bind-sut fabric:2.5
```

## Phase 2: Network Configuration Files

We must create two separate network configuration files (`networkConfig.yaml`) for Caliper to target both architectures.

### 2.1 Single-Channel Network Config (`network-single.yaml`)
- **Port:** `9090`
- **Channel:** `crowdfunding-channel`
- **Chaincode:** `crowdfunding`
- **Identities:** Uses the `_wallets/startuporg` and `_gateways/startuporg_gateway.yaml` generated by the single-channel deployment script.

### 2.2 Multi-Channel Network Config (`network-multi.yaml`)
- **Port:** `8080`
- **Channels:** Target specific channels where the transactions happen (e.g., `common-channel` or `startup-validator-channel`).
- **Chaincodes:** Maps to the isolated chaincodes (`startup`, `investor`, `validator`, `platform`).
- **Identities:** Uses the new multi-channel `_wallets` and `_gateways` directories.

## Phase 3: Workload Modules

We will create Node.js workload scripts (simulating user behavior) to be triggered by Caliper workers:

1. **`createStartup.js`**: Submits `CreateStartup` transactions using randomized IDs.
2. **`createCampaign.js`**: Submits `CreateCampaign` transactions (requires Startup creation first).
3. **`registerInvestor.js`**: Submits `RegisterInvestor` transactions with the SEBI compliant annual income (`> 20000000`).
4. **`makeInvestment.js`**: Triggers the `MakeInvestment` cross-channel routing.

## Phase 4: Test Benchmarks

We will define a benchmark configuration file (`benchconfig.yaml`) containing 3 rounds:

1. **Low Load (Performance Check)**
   - **Transactions:** 50
   - **Send Rate:** Fixed rate of 10 TPS
   - **Goal:** Verify that basic end-to-end functionality executes flawlessly with zero latency spikes.

2. **Medium Load (Performance Test)**
   - **Transactions:** 100
   - **Send Rate:** Fixed rate of 25 TPS
   - **Goal:** Measure block-cutting performance and orderer batching efficiency.

3. **Stress Load (Stress Test)**
   - **Transactions:** 1000
   - **Send Rate:** Fixed rate of 100+ TPS (or using rate controllers like `txDuration` or `maximumRate`).
   - **Goal:** Overload the Microfab container to find the maximum theoretical TPS before network degradation or failure occurs.

## Phase 5: Execution Commands

To run the benchmarks, we will use the following Caliper CLI commands:

**For Single-Channel:**
```bash
npx caliper launch manager \
    --caliper-workspace ./ \
    --caliper-networkconfig network-single.yaml \
    --caliper-benchconfig benchconfig.yaml \
    --caliper-flow-only-test \
    --caliper-fabric-gateway-enabled
```

**For Multi-Channel:**
```bash
npx caliper launch manager \
    --caliper-workspace ./ \
    --caliper-networkconfig network-multi.yaml \
    --caliper-benchconfig benchconfig.yaml \
    --caliper-flow-only-test \
    --caliper-fabric-gateway-enabled
```

Once the runs complete, Caliper automatically generates a `report.html` which we will use to directly compare the routing overhead of the multi-channel architecture against the single-channel baseline.
